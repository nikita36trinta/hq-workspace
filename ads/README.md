# Ads — пайплайн создания рекламных кампаний (Яндекс.Директ)

Переиспользуемый модуль + плейбук для запуска кампаний в Директе через API v5. Вобрал всё, что
наработали на ЧистаяСделка (2026-07). Самодостаточный (`direct.py`), как `analytics`/`mailer`.
Связка с [[reference_analytics_pipeline]]: у кампаний уникальный `utm_campaign` → выручка
раздельно в дашборде аналитики (матрица кампаний + drill-down).

## Быстрый старт
```python
from direct import Direct, Brief, GEO_MSK_SPB
d = Direct()                                   # токен из env YANDEX_DIRECT_TOKEN
cid = d.create_campaign(Brief(
    name="Проект — Поиск ГОРЯЧИЙ",
    utm_campaign="proj_hot",                   # УНИКАЛЬНЫЙ — иначе кампании сольются в дашборде
    landing="https://project.ru",
    weekly_rub=15000, geo=GEO_MSK_SPB,
    groups=[{"name":"Горячий интент",
             "keywords":["ключевая фраза 1","ключевая фраза 2"],
             "title":"Заголовок ≤56","title2":"Уточнение ≤30","text":"Текст ≤81. Без гарантий."}]))
d.disable_autotargeting(cid)                   # ПОИСК: выключить (мусор). РСЯ: оставить.
# ⚠️ launch() = деньги. Только с согласия человека и при пополненном счёте!
d.launch(cid)                                  # модерация объявлений + resume → «Идут показы»
```
Черновик (`create_campaign` без `launch`) **не тратит и не показывается** — можно спокойно ревьюить.

## Аккаунт / доступ
- Токен уровня аккаунта в env `YANDEX_DIRECT_TOKEN` (аккаунт mihaeljordan23 — общий на все проекты
  digiterium; кампании разных проектов живут в одном аккаунте, различаются по имени/utm).
- Гейт `YANDEX_DIRECT_ENABLED` — это флаг в коде TourSniper, НЕ ограничение Яндекса. Прямые v5-вызовы
  (`direct.py`) им не ограничены. См. [[reference_yandex_direct_api]].
- Баланс — **общий счёт** (SHARED_ACCOUNT_FUNDS). Есть овердрафт. Пополнять — только человек (ввод
  платёжных данных). Забрать 30k welcome-промо ДО первого пополнения ([[feedback_yandex_welcome_promo]]).

## Best-practices (проверено)
1. **Структура:** одна кампания = один интент/тема. Разделяй ГОРЯЧИЙ (транзакц.) и информационный —
   их нельзя оптимизировать вместе. Инфо-фразы («как проверить», «риски») в горячую НЕ клади — это
   DIY-читатели, кликают и уходят.
2. **Автотаргетинг:** Яндекс авто-добавляет к группам ПОИСКА → мусорный околотрафик. `disable_autotargeting()`.
   В РСЯ автотаргет оставляют.
3. **Стратегия:** старт на «Максимум кликов» (`WB_MAXIMUM_CLICKS` + недельный лимит). Автостратегии
   на конверсии («Максимум конверсий»/CPA) требуют **~10 конверсий/неделю** — на старте их нет, не
   обучатся. Переходить на конверсии, когда набрался объём; обучать на промежуточную цель (превью) +
   офлайн-конверсии по ClientId (реальные оплаты).
4. **Минус-слова:** `DEFAULT_NEGATIVES` (бесплатно/самостоятельно/госуслуги/как/скачать/образец/…).
5. **Гео:** `GEO_MSK_SPB` (Мск+МО+СПб+Ленобл) для высокоплатёжеспособных ниш; `GEO_RU` для РСЯ.
6. **Уникальный utm_campaign** на кампанию → раздельная выручка в дашборде аналитики.
7. **Цена клика:** дешёвый CPC (5₽) на «Максимум кликов» = мусор (покупает самые дешёвые клики).
   Чистые кампании дают выше CPC (реальный интент) — это правильно, не пугаться.
8. **Бюджет менять редко и только в начале недели** (ресёрч 2026-07). Любая правка недельного
   лимита запускает «рестарт трат»: система заново ищет цену и в тот же день может выкупить
   до 35%+35% лимита. Официальная рекомендация — не чаще раза в две-три недели. Гарантия
   средней цены клика действует, только если кампанию всю неделю не трогали, — поэтому каждая
   правка ещё и обнуляет эту гарантию.
9. **Поднятие бюджета НЕ удешевляет тест, а ускоряет его** — и обычно поднимает CPC: чтобы
   потратить больше за то же время, аукцион берёт клики дороже. Нужное число оплат для вывода
   от бюджета не зависит. Если цель — «дешевле проверить гипотезу», бюджет не трогай; если
   «быстрее» — поднимай, но считай, что цена клика вырастет.
10. **Убыточную кампанию отключают, а не оптимизируют бюджетом.** Считай выручку на рубль
   расхода по utm_campaign в своём дашборде, а не CPA в интерфейсе Директа: Директ не знает
   ни апселлов, ни возвратов.

## ⚠️ Модерация — граница (ниша недвижимости/юруслуг, проверено 2026-07)
- **Абсолютные гарантии** («100%», «гарантируем результат») — режет. Убрать превосходные степени.
- **Текст объявления = лендингу** (переоценка при изменении сайта).
- **Ниша ЕГРН/Росреестр/кадастр — КЛЮЧЕВОЕ различие:**
  - ❌ **БЛОК:** «выписка ЕГРН онлайн», «данные из ЕГРН» = позиционирование как ПРОДАВЕЦ официальных
    выписок Росреестра (запрещено согласно законодательству страны таргетинга / до документов).
  - ✅ **ПРОХОДИТ:** «проверка ... по кадастру / Росреестру / данные ЕГРН» = фрейм ПРОВЕРКИ (данные
    как ИСТОЧНИК проверки, не товар). Даже пограничные «проверка по Росреестру», «проверка: данные
    ЕГРН» прошли — блокирует именно слово «ВЫПИСКА».
  - Лицензия риелтора для due-diligence НЕ нужна (мы не риелтор, не продаём объекты).
- **Проба формулировок:** запусти пачку групп от безопасной к пограничной (см. ниже) →
  `moderation_status(cid)` покажет что прошло/отклонили → оставь проходящие, слабые убери.

## Проба формулировок на модерацию (probe)
Чтобы выбить максимум дозволенного — создай кампанию с несколькими группами (по формулировке),
запусти, проверь статусы:
```python
cid = d.create_campaign(Brief(name="… формулировки (тест)", utm_campaign="proj_probe", landing="…",
    groups=[
      {"name":"v1_safe",   "keywords":[...], "title":"…безопасная…", ...},
      {"name":"v2_border", "keywords":[...], "title":"…пограничная…", ...},
      # … до самой острой
    ]))
d.disable_autotargeting(cid); d.launch(cid)
# через 15–60 мин:
for s in d.moderation_status(cid):
    print(s["verdict"], s["clarification"])   # passed / rejected / moderation
```

## Рабочий процесс (сценарий запуска)
1. `create_campaign(brief)` каждой кампании (черновики — безопасно).
2. `disable_autotargeting(cid)` на поисковых.
3. Показать человеку / отревьюить в интерфейсе Директа.
4. **Пополнить счёт** (человек) + welcome-промо.
5. `launch(cid)` — модерация + активация (с согласия).
6. Через 15–60 мин — `moderation_status()` (что прошло).
7. Через 3–7 дней — дашборд аналитики «Матрица кампаний»: какая по utm даёт визиты/оплаты/выручку;
   слабые `suspend()`/`delete()`, бюджет — на рабочие (`set_weekly_budget`).

## Гочи
- `create_campaign` иногда ловит transient «Сервис временно недоступен» (error 1000) — в `call()` есть
  ретрай, но при сбое ПОСРЕДИ создания объявление может залипнуть в State=OFF (не разлочивается ни
  `resume`, ни toggle). Лечение: удалить кампанию и пересоздать ЧИСТЫМ прогоном (не чинить залипшую).
- `Date.now()`/argless `date`/random недоступны в некоторых окружениях-скриптах — `start_date`
  передавай явной ISO-строкой при необходимости.
- **Мёртвая цель в Метрике = слепая автостратегия.** Перед переводом кампании на конверсии
  проверь, что выбранная цель реально срабатывает (`stat/v1/data` + `ym:s:goalNreaches` за 30
  дней). Цель, которой нет в коде, даёт ноль достижений и стратегия учиться не на чем.
- РСЯ по ключам ≠ ретаргетинг. Настоящий ретаргетинг («смотрел превью, не купил») требует сначала
  сегмент в Метрике/Аудиториях — через API кампаний не сделать.
