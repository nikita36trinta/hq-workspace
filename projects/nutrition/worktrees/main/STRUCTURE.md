# Nutrition — структура проекта (4 лендинга + сравнение конверсии)

## Идея
Один продукт (персональный план питания), **4 разных лендинга под 4 разных угла**.
На каждый лендинг льём ОТДЕЛЬНЫЙ рекламный трафик (своя кампания Директа) и смотрим,
какой угол лучше конвертит холодный клик. Это тест ПОЗИЦИОНИРОВАНИЯ, не только дизайна
(урок Наследства: угол/оффер важнее верстки).

## 4 угла (гипотезы позиционирования)
| ID | Слаг | Угол / кому | Хук |
|----|------|-------------|-----|
| L1 | `fitness` | Спорт/форма | «Питание под ваши тренировки — набрать форму, а не голодать» |
| L2 | `slim` | Похудение мягко | «Снизить вес без голода — сытное меню под ваш дефицит» |
| L3 | `energy` | Здоровье/энергия (wellness) | «Наладить питание и энергию — регулярность, меньше скачков сахара» |
| L4 | `easy` | Экономия времени / без готовки | «Больше не думать, что готовить — меню + список покупок на неделю» |

Все 4 ведут в ОДИН квиз → тот же продукт (план на неделю) → тот же пейволл (490₽ трипваер +
подписка 449₽/мес на обновление меню). Отличается только hero/копирайт/картинки под угол.

## Архитектура (переиспользуем движок astro + сплит-логику sdelka)
```
GET /            → редирект на дефолтный лендинг (или выбор)
GET /l/{slug}    → лендинг под угол (static/landings/{slug}.html); инкремент visit_{slug}
GET /quiz        → общий квиз (анкета: цель/вес/рост/активность/предпочтения/аллергии/email)
POST /api/lead   → захват лида {email, quiz-данные, landing, src(ad/organic)} → leads.jsonl
                   (оплата пока заглушка; при подключении ЮKassa — через add-payments пайплайн)
GET /api/health
GET /admin/stats?token=  → воронка ПО ЛЕНДИНГАМ: визиты→quiz_start→lead→(pay), CVR каждого
GET /privacy /consent /offer  → юр-страницы (152-ФЗ, оферта) — как в astro
```

## Как считаем «какой лучше»
- **Знаменатель:** серверный счётчик визитов на каждый лендинг (`visit_{slug}`), плюс Метрика.
- **Числитель воронки:** goal-события с меткой landing → `quiz_start`, `quiz_done`, `lead`, `pay`.
- **Метрика решения:** lead-rate и (когда будет оплата) ₽/визит по каждому лендингу.
- Реклама/органика — как в sdelka (метка src по yclid/utm), можно смотреть раздельно.
- Каждый лендинг = своя кампания Директа (свой UTM `utm_content={slug}`) → чистое сравнение.

## Что переиспользуем 1:1
- **Движок квиза** (astro): hero → шаги → анимация сборки → тизер → пейволл → подписка.
- **Сплит-статистика** (sdelka abstats): счётчики + per-landing разбивка + ad/organic.
- **Юр-слой** (astro/golive-legal): privacy/consent/offer, самозанятый, дисклеймер «не медуслуга».
- **Пайплайн add-payments** (доктрина с pay-first/две доставки/reconciliation) — когда включим оплату.

## Модерация (жёстко)
Продавать «персональный план питания / меню / расчёт КБЖУ / дневник». НИКОГДА не обещать
«минус N кг», сроки, «избавит от болезни». Дисклеймер «справочные материалы, не медуслуга».

## Порядок сборки (после выбора дизайн-референсов)
1. Выбрать эстетику по трекеру референсов (Zoe/Sakara/Noom/…).
2. Сгенерить единый набор food-ассетов (Flux 2, один style-anchor) + hero-луп (Kling).
3. Собрать 4 лендинга (hero+копирайт под угол, общий квиз-движок).
4. LLM-генерация меню по анкете (промпт + шаблоны), PDF-отчёт.
5. Домен + Метрика + 4 черновые кампании Директа (по одной на угол) → модерация.
6. ЮKassa (запрос про категорию — питание проще эзотерики) → add-payments.

## Статус скелета

- `static/landings/{fitness,slim,energy,easy}.html` — слоты лендингов (пока = наши прототипы, переугловать). ⏳
- Дизайн/ассеты/квиз-контент — после выбора референсов.
