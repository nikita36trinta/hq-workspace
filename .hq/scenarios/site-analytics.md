# Site analytics — Метрика-счётчики, цели, привязка к Директу

> **Status: PROVEN (3 сайта 2026-07-04).** Host-step flow (API-вызовы), не
> контейнерный пайплайн: токен Метрики живёт ТОЛЬКО на toursniper-проде
> (`/root/travel-bot/.env` → `YANDEX_METRIKA_OAUTH_TOKEN`) — не
> материализовать локально; все curl-вызовы гонять по ssh с того сервера.

## What it accomplishes

Для каждого сайта: счётчик Метрики → цели по РЕАЛЬНЫМ событиям кода →
ID вшит во фронт → привязка счётчика к кампании Директа. После этого цепочка
Директ(UTM) → визит → микроконверсии → pay_success анализируется корректно.

## The flow

```mermaid
flowchart TD
  create[Management API: POST /counters — счётчик на домен] --> inv[grep кода: какие goal('…') сайт РЕАЛЬНО шлёт]
  inv --> goals[POST /counter/id/goals type=action — ровно эти имена]
  goals --> embed[вшить METRIKA_ID во фронт + deploy]
  embed --> ret[pay_success на /pay/return — только real succeeded]
  ret --> link[Direct campaigns.update: TextCampaign.CounterIds]
```

## Hard-won gotchas

- **Цели создавай по именам, которые сайт УЖЕ шлёт** (`grep "goal('"` по
  фронту), а не по абстрактному списку — иначе цели мёртвые, события летят в
  никуда. Тип цели: `action`, condition `exact` = имя события.
- **Страница возврата с оплаты — слепое пятно №1**: она часто вне общего
  layout (inline HTML / отдельный статик) и НЕ несёт счётчик. Обязательно:
  init счётчика + `reachGoal('pay_success')` строго при перепроверенном
  `succeeded` (bypass/canceled — нет), sessionStorage-guard от повторов.
  (Теперь это требование доктрины add-payments.)
- **Счётчик ↔ кампания Директа не связываются сами**: без
  `campaigns.update {TextCampaign:{CounterIds:{Items:[id]}}}` Директ не видит
  конверсий и автостратегии не учатся. Обязательный шаг.
- Модель загрузки — информационная (решение оператора): Метрика грузится
  сразу, баннер однокнопочный; политики должны описывать именно эту модель
  (доктрина golive-legal обновлена).
- Разные страницы одного сайта могут иметь СВОИ копии cookie/metrika-логики с
  разными именами переменных (init-паттерны отличались на всех трёх сайтах) —
  правки грепать по всем шаблонам, не только по лендингу.
- Известное ограничение: pay_success фиксируется на странице возврата — если
  вкладку закрыли до возврата, конверсия не попадёт в Метрику (webhook заказ
  пометит). Лечится офлайн-конверсиями (как у TourSniper) — TODO при масштабе.
